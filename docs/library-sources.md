## Recommendation

**Recommendation based on verified observations:** prioritize **Brooklyn**, but scope the first adapter as a limited HTML prototype: fetch the homepage's linked upcoming `/calendar/…` pages, parse the readable event content and calendar block, deduplicate by official permalink, preserve America/New_York times, and retain the exact event-specific cost evidence. Use conditional requests with the observed ETag/Last-Modified, respect the main host's 30-second crawl delay, and avoid re-fetching inside the observed three-hour freshness period. These are proposed adapter behaviors, not an implemented or tested parser.

**Verified limits:** this discovery route is editorially selected and cannot support exhaustive keyword results or a reliable inventory count. Search JSON is denied; Queens' feed is structurally valid but empty; NYPL is protected. **Unverified / required before a comprehensive adapter:** a library-approved Brooklyn collection transport and reuse conditions; successful date/branch/pagination semantics; a valid event-level “free” quote; populated Queens feed/JSON and its cancellation/currentness behavior; an approved readable NYPL events transport. Do not promote any of these findings into claims of zero martial arts events or universal free admission.

**Unverified across all three:** no documented public events API was established in this bounded check. Auxiliary discovery (`https://api.nypl.org/`, no response headers/body captured; `https://nypl.github.io/nyplapis/`, HTTP 404; a public search page returning a JavaScript redirect shell) supplied no additional event evidence. No real Queens/NYPL upcoming examples are fabricated to fill the requested slots.
